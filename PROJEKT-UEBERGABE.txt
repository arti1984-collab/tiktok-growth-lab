TIKTOK GROWTH LAB
Uebergabedatei fuer eine andere KI
Stand: 04.11.2026, Version 2.13.0, Branch main


1. WAS DAS PROJEKT IST
----------------------
Ein lokales Werkzeug fuer TikTok-Wachstum. Es liest Profil und Videos direkt
von tiktok.com, rechnet Kennzahlen aus, verfolgt Follower ueber die Zeit und
laesst eine KI daraus Strategie, Ideen, Captions, Hooks, Plaene und Hashtags
schreiben.

Zwei Oberflaechen, ein gemeinsamer Kern:
- Web-Dashboard (React, laeuft im Browser auf 127.0.0.1:8787)
- Windows-Programm (Electron, portable .exe, startet den Server selbst)

Die Android-App wurde am 04.11.2026 aus dem Repo genommen. Sie liegt nur noch
lokal im Ordner android/ und wird nicht mehr gebaut oder ausgeliefert.

Alles ist lokal. Es gibt kein Benutzerkonto, keine Datenbank in der Cloud und
keine Telemetrie. Nach aussen gehen nur drei Dinge: Anfragen an tiktok.com,
Anfragen an den KI-Anbieter, dessen Key der Nutzer selbst eintraegt, und die
Update-Pruefung an api.github.com.

Das Projekt liegt privat auf GitHub: arti1984-collab/tiktok-growth-lab


2. TECHNIK
----------
Web/Server: Node 24, Express 4, TypeScript (tsx), React 19, Vite 7,
handgeschriebenes CSS, keine UI-Bibliothek.
Desktop: Electron 45, electron-builder (target portable), self-signed exe.

Befehle (Projektwurzel):

  npm run dist           Web + Server + portable exe nach release/ + Signatur

4. DATENFLUSS
-------------
Scan (Web/Desktop):
  1. GET Profilseite, daraus secUid, Follower, Nickname, Avatar.
  2. GET https://www.tiktok.com/api/creator/item_list/?aid=1988&secUid=...&type=1&count=15&cursor=0
     Das ist der einzige Weg, der ohne Signatur funktioniert. post/item_list
     liefert leer, deshalb nicht verwenden.
  3. Optional einzelne Video-URLs ueber webapp.video-detail -> itemInfo.itemStruct.
  4. computeMetrics rechnet lokal, Antwort geht an den Browser.
  5. Bei aktivem Tracking landet ein Snapshot in data/store.json.

KI-Aufruf:
  POST /api/ai mit { mode, handle, payload }. Der Server baut System- und
  Nutzerprompt, schickt sie an die konfigurierte Basis-URL und versucht, JSON
  aus der Antwort zu loesen. Rueckgabe: { model, parsed, result }.
  parsed=false heisst: kein reines JSON, die Antwort wird als Text angezeigt.

Wichtige Routen (Details in server/index.ts):
  GET  /api/status         Version, Zeitzone, KI-Zustand, Scraper-Zustand
  POST /api/scan           Account scannen
  GET  /api/last-scan      letzter Scan im Speicher (nach Neustart leer)
  POST /api/ai             KI-Antwort erzeugen
  GET  /api/ai/models      verfuegbare Modelle des Anbieters
  POST /api/ai/scan-free   Modellliste nach kostenlosen Modellen filtern
  GET  /api/update         neueste Veroeffentlichung, laedt exe im Hintergrund
  POST /api/update/token   prueft, ob das Token das Repo lesen darf
  POST /api/update/restart tauscht die exe beim Beenden, dann Neustart
  GET/POST /api/watchlist  Account verfolgen, messen, entfernen
  GET/POST /api/settings   Einstellungen lesen und schreiben


5. OBERFLAECHEN UND IHRE PUNKTE
-------------------------------
Reiter im Web: Scan & Analyse, Wachstum, KI-Studio, Einstellungen, Anleitung.
Die Anleitung im Programm beschreibt jeden Punkt; wer etwas umbaut, sollte
sie mitziehen.

Scan: Handle-Feld, optionale Video-Links, Scan starten, Score mit Messlatte,
Kennzahlenkacheln, Hinweise aus den Daten, beste Zeitfenster, Videolaenge,
Hashtag-Nutzung, Videoliste mit Link ins Original.

Wachstum: Account hinzufuegen, alle messen, Delta 7 Tage, Delta seit erster
Messung, Detailreihe mit allen Messpunkten, entfernen.

KI-Studio: sieben Modi (strategy, audit, ideas, caption, hooks, calendar,
hashtags). Eingaben: Thema, Nische, Tonalitaet, Ziel, Anzahl. Ergebnis als
JSON, "Kopieren" und "Als Textdatei speichern". Der Hashtag-Bereich als eigene
Karte wurde in 1.5.2 entfernt, Hashtags laufen ueber den Modus-Chip.

Einstellungen: Anbieter-Karten (Google AI Studio, Groq, OpenRouter), Basis-URL,
Modell, Key (wird nie zurueckgegeben), Pause zwischen Anfragen, Zeitzone,
optional Cookie, Systemstatus mit Version aus package.json.

8. BEKANNTE GRENZEN
-------------------
- Ohne Login hoechstens 15 Videos pro Account. Mehr nur mit Session-Cookie.
- /api/last-scan ist leer, solange der Server nicht neu gestartet wurde.
- Downloads im eingebetteten Browserfenster von Werkzeugen wie diesem werden
  teils verworfen. Das ist keine Eigenschaft der App: in der exe und im
  normalen Browser speichert der Export regulaer.
- Ohne API-Key antwortet das KI-Studio nicht, Scannen und Rechnen gehen ohne.
